# 维护准则

要修改 Twig 本身（规则、页面、代码、说明文档）时先读本文件。先分清身份：用户自称维护者，或在 Twig 源码仓库里工作时，按“维护者”一节；其余情况都按“用户”一节。

## 用户

本目录由 Twig 扩展安装，扩展升级时整体覆盖、卸载时删除，直接改这里的文件会丢失。

- 想调整 AI 的写法、风格，写进本目录的 `个人偏好.md`（没有就新建）。它不会被覆盖，能调什么见 `SKILL.md`。
- 页面的颜色、布局在扩展内部，个人偏好改不了；有需要到 GitHub 仓库提 issue。

## 维护者

### 说明文档

| 文件 | 读者 | 只写什么 |
|---|---|---|
| `README.md` | 商店访客 | 解决什么问题、核心功能、怎么安装和开始用；不写实现细节和规则细节 |
| `SKILL.md` | AI | 何时触发、按什么顺序读哪些文件 |
| `书写要求.md` | AI | 写 Twig 文件的全部规则 |
| `模板.md` | AI | 新 Twig 文件的骨架 |
| `维护准则.md` | AI | 本文件 |

- README 保持简洁，只写核心；新功能先问是否值得写进 README，值得也只写一句。
- 各文件分工独立：同一件事只在一个文件里写，其他文件需要时指过去，不复述。

### 代码

| 文件 | 职责 |
|---|---|
| `skill/build.cjs` | 解析源文件（`parse`、`figurePages`）、检查格式（`check`）、生成页面（`toHtml`）；命令行和扩展共用 |
| `skill/viewer.html` | 页面：样式和脚本，按注释标题分节（公式、跳转原文、行内格式、块级排版、画树、知识卡片、缩放）；KaTeX 版本在 `<head>` |
| `extension.js` | 只放与 VSCode 交互的部分：命令、预览面板、新建时的搜索框、打开 PDF（`openPdf`）、安装 skill |
| `zotero.js` | 通过 Zotero 本地 API 列文件夹、搜索文献、取 PDF 路径和所在分类，由 PDF 路径推出数据目录，把引文、`pdf`、`firstPage` 填进模板；不用 vscode 接口 |
| `uninstall.js` | 卸载清理：删掉装进各家 AI 的规则文件，保留 `个人偏好.md`，跳过链接到仓库的目录 |

- 新功能按职责放进对应文件，再放进文件中对应的一节；没有合适的节时新开一节并加注释标题。
- 两处必须一致的内容（如 `viewer.html` 和 `build.cjs` 中的 `REF`，`extension.js` 和 `uninstall.js` 中的 `AI_HOMES`）在两处注释里互相注明。
- 改了写法支持，同步改 `书写要求.md` 的“页面支持的写法”表。
- 改了 `viewer.html` 或 `build.cjs`，用 `node skill/build.cjs <已有的 _twig.md>` 生成页面检查，不应出现提示。
- `个人偏好.md` 不进仓库、不进 vsix，否则会覆盖用户自己的偏好。
- 安装和卸载只处理当前 `skill/` 里有的文件。改名或删掉其中的文件时，在 `extension.js` 的 `installSkill` 和 `uninstall.js` 里加上旧文件名，让升级和卸载时一并删掉，否则旧文件会一直留在用户目录里。
