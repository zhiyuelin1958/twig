# 书写要求

**这是什么**：用户精读论文时会连续追问，概念套概念，对话越长越乱。Twig 替用户记住“主线读到哪、从哪里岔出去、每个分叉学到了什么”：论文各节沿竖线排成主干，追问向右分叉，每个节点有一张知识卡片。读完后再用提问清单检验用户是否真正掌握。

**总原则**：真实第一，其次精炼，再次可理解。没有出处不写；原文没说、由 AI 推出的内容标【推断】。宁可少写，不可写错。

## 产出

三个文件放在同一个文件夹，编号按其中已有的 Twig 文件顺延；已有文件就接着写，不覆盖。用户用扩展的“新建 Twig”建文件时，位置已按规则定好：根目录（VSCode 设置 `twig.folder`，没设时为 Zotero 数据目录旁的 `Twig阅读整理/`）下按 Zotero 分类建的子文件夹。AI 自己新建时照这个规则放；不清楚时问用户：

- `<编号>_<作者年份>_twig.md`：源文件，所有内容写在这里；用户在 VSCode 里用 Twig 扩展实时预览，不需要每轮生成页面。用户要分享或要求生成页面时，运行 `node <skill 目录>/build.cjs <twig.md 路径>`，在同一文件夹生成同名 `.html`。
- `<编号>_<作者年份>_提问清单.md`、`参考答案.md`：读完后写，两者分文件，避免用户答题时看到答案。

## 流程

1. **开始**：只问一句“读哪篇、从哪一节开始”，其余不多问。用户常用扩展的“新建 Twig”从 Zotero 建好文件，引文、`pdf`、`firstPage` 已填好；`firstPage` 取自 Zotero 的页码字段，PDF 带封面页或期刊用文章编号时会不对，要打开 PDF 第 1 页核对。用“从 PDF 新建”建的文件只填了 `pdf`，标题、引文、`firstPage` 读 PDF 后填。没有文件时，新论文从 `模板.md` 复制起步，保留开头给 AI 的注释，填好元信息 `pdf`、`firstPage`（PDF 第 1 页的期刊页码）。已有 Twig 文件（如开新对话接着读）时，先读元信息和全文主线卡片，从 `current` 接着读。
2. **先写全文主线**：完整读全文（含图表、附录；PDF 缺公式或图注时渲染成图看），把每张图、表所在的期刊页码登记到元信息 `figures`，写好第一个节点“全文主线”的卡片。它是用户读每一节时的地图。
3. **每轮问答**：
   - 详细讲解写在对话里，树里只放整理好的结论，两者不必逐字相同；
   - 增改节点后更新开头的 `progress`（主线读到哪）和 `current`（当前所在节点的 id）；
   - 回复末尾只写一行 `当前：主线 › … › …`，不把整棵树贴进对话。
4. **读完**：写提问清单与参考答案，然后核验。

## 树的结构

树要反映**知识的依赖关系**，而不是对话记录。用户回头看图时，应该能顺着线理解“先懂什么、才能懂什么”。

- **主干**：第一个节点“全文主线”；之后按论文顺序每节一个节点，标题写成 `§x 节名：这节在做什么`。
- **何时入树**：追问引出新概念或新问题时新增节点；对同一问题的反复澄清并入原节点；闲聊、操作类问题不记。
- **按依赖挂**：新节点挂在它依赖的概念下，而不是当时正在读的节点下。例如“矩”是对粒子谱的积分，就挂在“粒子谱”下面。同一层里先修概念在前，其余按论文顺序，可以调换。
- **先问再动**：结构调整由用户决定。
  - 新问题和已有节点适合合并时，问“是否与「xx」合并？”；
  - 新问题琐碎、不影响理解主线时，问“是否放入图中？”；
  - 发现已有节点挂错层级时，说明理由后问是否调整。
- **超出本文**：用户感兴趣但明显超出本文范围的问题，经用户同意后入树，加 `status=extra`（米黄色方框），卡片写清与本文的联系，未核实内容标“待确认”。
- **暂挂与回收**：一时弄不懂或不影响主线的问题，加 `status=pending` 并在卡片写明原因。一个分叉弄懂或暂挂后，回复里说一句“回到主线：…”，并把 `current` 改回上层节点。
- **标题**：追问节点用问句，约 18 字以内；方框里最多显示两行。

## 知识卡片

卡片是用户以后复习时真正读的东西，要能**单独读懂**，不能只是备忘录式的一句话。

- **内容**：讲清“是什么、为什么、在本文里起什么作用”；有数值就写数值。不铺陈，同一件事只讲一遍。
- **来源**：每段之前单独一行标来源，让用户分得清哪些是论文说的、哪些是补充的：
  - `【原文 · §2b p.994「the slope parameter is diagnosed」；Tab. 1】`：论文内容，出处精确到节、图表、页。每个页码后用「」照抄该处原文中连续 4–8 个英文词，用户点页码时 PDF 会定位到这一行；选同一行内、不跨行断词、不含公式和特殊符号的句子；
  - `【背景】`：论文之外的通用知识；
  - `【推断】`：AI 推出且未核实的内容，页面上显示为橙色提醒。
- **链接**：正文提到其他节点的概念时写成卡片链接，用户点一下就能跳过去。子节点尽量在父卡片正文中自然引出；没引出的，页面会自动列在卡片底部。
- **排版**：并列几点用 `- ` 列表，有先后顺序用 `1. `，多个对象的比较用表格；只加粗结论性词句；一个意思一段，不要把罗列内容挤成一段话。长卡片用 `###`、`####` 分节，不用 `## `（它留给节点标题，写在卡片里会原样显示）。

页面支持的写法：

| 写法 | 效果 |
|---|---|
| `## 标题 {#id parent=父id status=pending}` | 节点，整行写完；不写 parent 即为主干；`status=pending` 暂挂（虚线框），`status=extra` 超出本文（米黄框）。id 只用英文字母、数字、`_`、`-`，写中文这一行就不算节点 |
| `[文字](#id)` | 卡片链接 |
| `$N_{0r}$`；`$$…$$`（可跨多行） | 行内公式；行间公式（浅蓝框，KaTeX 排版） |
| `**粗**` `*斜*` `` `码` `` `> 引用` `---` 表格 列表 | 常规 Markdown |
| `p.994「…」`、`p.998–999`、`Fig. 8`、`Figs. 8 and 9`、`Tab. 1` | 卡片里任何位置都可点（需 PDF Viewer 扩展）：页码跳到该页并定位「」里的原文，引文本身不显示；图表跳到 `figures` 登记的页，子图 `Fig. 8a` 按 Fig. 8 |
| 元信息 `pdf`、`firstPage`、`figures` | 论文 PDF 相对 Twig 文件的路径；PDF 第 1 页的期刊页码；各图表的期刊页码，如 `Fig. 1=993, Tab. 1=994, Fig. A1=1006` |

行内公式换成 Unicode 字符显示，只支持上下标、希腊字母、常用运算符、`\mathrm{}`，用来写简单的量和关系式。分数、积分上下限、根号、多行推导写成行间公式，按标准 LaTeX 写，由 KaTeX 排版（多行用 `aligned` 环境）。

## 全文主线卡片

它取代单独的主线文件，让用户三分钟内知道这篇论文讲什么、哪里该精读。依次包含：

1. 引用框：论文完整引文、出处标记说明；
2. 一句话主题；
3. 论文地图：表格“节｜页｜这一节在做什么｜读法”，并指出最关键的几张图；
4. 背景 → 问题 → 方法 → 证据链（表格“结论｜证据”）→ 结论 → 局限；
5. 阅读边界：可略读、不要求弄懂、必须弄懂；
6. 核心概念：表格“概念｜一句话”，概念链接到对应节点；
7. 三分钟复述稿；
8. 待确认：推断与未核实的内容。

关键结论和数值后用方括号标出处，如 `[§4b p.998「…」；Fig. 8]`。

## 提问清单与参考答案

目的是检验用户是否真正读懂，而不是考记忆。

- 20–30 题；清单开头注明“先不看参考答案，回答时指出章节、图或表”。
- 由浅入深分层：动机与问题 → 方法设计 → 结论与证据（哪张图支持哪个结论）→ 原文细节 → 局限与迁移。
- **一题一问**：每题只考一件事，至多带两个紧密相关的小问。
- **细节题限量**：不超过 3 题，只考有意义的数，并要求说明含义（如“保留率 17.7% 说明了什么”），不考数字清单。
- **回收读者的问题**：对话中纠正过的错误前提，挑涉及核心概念或常见误读的出辨析题，单纯读错数字、看错表格的不出；暂挂节点逐个决定出题，或在清单末尾注明不出的理由。
- **理解型题**：至少 3 题是反事实、用自己的话解释或迁移题。
- 每题都能在原文定位，答案逐题带出处。
- 用户作答后，对照原文批改并引出处，指出缺漏，不替用户补全。

## 核验

交付前回到原文，逐条核对卡片和答案中的数值、符号、图表号、出处与「」引文，不凭印象；仍不能确认的标“待确认”或【推断】。运行 `build.cjs` 时不应出现任何提示。
