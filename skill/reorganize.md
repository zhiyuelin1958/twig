# 整理

追问按提问顺序长出来，常常一张卡片答了几个问题、几张卡片讲同一件事、一个词先用后讲。整理是对一棵子树的**重新设计**：按概念重新切卡、按依赖重新排列、重写正文。原则：**删是决定，漏是事故**，每条内容的去向都要写明。一次只整理一棵子树，其余部分不动；写法仍照 `书写要求.md`。

## 1. 盘点

- 动笔前把 `_twig.md` 复制一份到系统临时目录，作为比对用的旧文件。
- 把子树每张卡片拆成编号知识点，一条只含一个论断，连同来源标记记下，如 `prior-3｜经验冰核公式在冷温下给出过大冰晶数｜原文 §2c p.1671`。清单只在对话里用，不写进文件。

## 2. 逐条定去向

每条知识点只能是以下之一：

| 去向 | 条件 |
|---|---|
| 保留 | 默认 |
| 合并到某条 | 与另一条说的是同一件事；留表述更好、出处更精确的一条 |
| 删除 | 理由只能是：重复；被后文取代；表述不清且不影响理解；对话残留（操作、闲聊）；离题 |
| 存疑 | 改标【推断】或“待确认” |

【原文】中涉及本文结论、数值的知识点不删，只能合并。

## 3. 重新切卡与排列

1. **切卡**：一张卡片一个概念或问题。一张答了几个问题的拆开，几张讲同一概念的合并；合并时保留一个 id，其余 id 的链接改指过去。
2. **依赖**：标出每张卡片**定义**的词和**用到**的词，“用到 → 定义”是一条依赖。
3. **层级**：概念挂在用到它的所有节点的最近公共上层之下，只被一处用到的挂在那处下面，连线不写 `rel`；由某节点引出的后续问题挂在它下面，标 `rel=next`；联想到的标 `rel=assoc`。
4. **同层顺序**：先修在前；无依赖时按“是什么 → 怎么来 → 怎么算 → 本文怎么用 → 拓展（extra）”；再按论文顺序。提问顺序不作依据。
5. **先讲后用**：按页面阅读顺序，任何词不得先用后讲；做不到的，在用到处加卡片链接。

## 4. 重写正文

- 第一句直接给答案，再展开。
- 链接所在的句子说明两张卡片的关系，不写“相关：××”。
- 知识点移到哪里，来源标记和「」引文跟到哪里，引文一字不改。
- 发现前后矛盾的说法，标出来问用户，不自行调和。
- 旧文件里的【背景】顺手改为【论文】【教材】或【推断】。

## 5. 交方案

写入文件前给用户三样东西，确认后才动：

1. 新子树草图：缩进列表，每行“标题 {#id rel status}”；移动、合并过的节点与新父节点的关系变了，`rel` 按 `书写要求.md` 的“连线”重新判断；
2. 节点变动表：`节点｜动作（拆 / 合 / 移 / 删 / 改名 / 改连线）｜新位置｜理由`；
3. 删除清单：`编号｜原知识点｜理由`，用户可整体确认，也可勾掉个别条目。

## 6. 核验

- 运行 `node <skill 目录>/build.cjs --compare <旧文件> <twig.md>`。它列出丢掉的节点和出现次数变少的「」引文；每一条都要能在确认过的删除清单或合并记录里找到，否则补回。
- 逐个检查【论文】标签下的内容：不带页码的，只能写题名层面的信息，具体结论、公式、数值改标【教材】或【推断】。
- 对照知识点清单逐条找到新位置，回复里报告“保留 x、合并 y、删除 z，全部有着落”。
- 更新 `progress`、`current`；运行 `build.cjs` 不应出现提示。
