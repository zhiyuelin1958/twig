# 工作台搭建

Twig 靠 AI 边读边改 `*_twig.md`，所以文件放在哪里会影响使用体验。本文说明推荐的布局和原因。

## 三条原则

1. **Twig 文件放在工作区里。** 工作区就是 VSCode 打开的文件夹。Claude Code 等 AI 默认只能读写工作区里的文件，工作区外的每次都要你确认；资源管理器和全局搜索也只看工作区。
2. **论文 PDF 最好也在工作区里。** 不在也能用，但 AI 读 PDF 时会弹确认，要把 PDF 所在的文件夹加给 AI（Claude Code 里运行 `/add-dir 文件夹路径` 并选择记住）。
3. **文献库的数据库不放进云盘。** Zotero 等软件的数据库正被软件读写时，网盘同步可能把它弄坏。它们的同步交给软件自带的功能。

不要用目录联接或符号链接把工作区外的文件夹“挂”进工作区：AI 工具通常按链接指向的真实位置判断，仍然算工作区外。

## 用文献库，不用云盘

```
科研/                  ← 用 VSCode 打开这个文件夹
├── Zotero/            ← Zotero 数据文件夹，PDF 在其中的 storage/
└── Twig阅读整理/      ← Twig 文件，按文献库的分类建子文件夹
```

- **Zotero 数据文件夹移进来**：Zotero 不会替你搬旧数据。先关掉 Zotero，把整个数据文件夹（含 `zotero.sqlite` 和 `storage/`）移进科研文件夹；再打开 Zotero，在 设置 → 高级 → 文件和文件夹 把数据存储位置改成自定义，指向新位置。重启后确认设置还在。
- **搜索排除 Zotero**：`storage/` 里有大量全文缓存，会混进搜索结果。在 VSCode 设置里给 `search.exclude` 加一项 `**/Zotero/**`。只影响搜索，资源管理器里照样能看到 PDF。
- **用 `.bib` 文件的**（JabRef，或从其他软件导出）：把 `.bib` 和 PDF 文件夹放进科研文件夹，代替上图的 `Zotero/`；设置 `twig.library` 选 `bibtex`，`twig.bibFile` 填 `.bib` 相对科研文件夹的路径。

## 用文献库，也用云盘

```
云盘/科研/             ← 用 VSCode 打开这个文件夹，随云盘同步
└── Twig阅读整理/

Zotero 数据文件夹       ← 留在本地，不进云盘
```

- **Zotero**：条目用 Zotero 自带的同步；PDF 用 Zotero 的文件同步，空间不够时选 WebDAV（如坚果云）。
- **PDF 在工作区外**：按原则 2 把 Zotero 数据文件夹下的 `storage/` 加给 AI。
- **换电脑接着读**：Twig 文件里记着 Zotero 的文献编号。另一台电脑上 PDF 的位置不同时，点出处会按编号向 Zotero 查这台电脑上的 PDF，需要 Zotero 开着。
- **用 `.bib` 文件的**：`.bib` 是普通文本文件，可以和 PDF 一起放进 `云盘/科研/`，路径按上一种布局设置。注意不要在两台电脑上同时改同一个 `.bib`，否则云盘会生成冲突副本。

## 不用文献库

```
科研/                  ← 用 VSCode 打开这个文件夹；用云盘时整个放进云盘
├── 论文/              ← PDF，可按主题分子文件夹
└── Twig阅读整理/
```

- 新建时选“从 PDF 新建”，引文等由 AI 读 PDF 后填。
- PDF 和 Twig 文件都在工作区里，用云盘时一起同步，换电脑也能直接跳到原文。
- 想把 PDF 和 Twig 文件放在一起的，也可以每篇论文一个文件夹。

## 用其他文献软件

EndNote、Mendeley、NoteExpress 等，Twig 不能直接读它们的库，有两种办法：

- **导出 `.bib`**：从软件里导出 BibTeX 文件，按上面用 `.bib` 文件的方式设置。导出的 `file` 字段里有 PDF 路径时，新建会自动填 `pdf`，否则留空，自己填或交给 AI。软件里改了条目要重新导出。
- **当作不用文献库**：库留在本地，正在读的 PDF 复制一份到 `论文/`，按“不用文献库”的布局放。多出一份 PDF，但路径在每台电脑上都对得上。

## 不按这些布局

在设置里搜索 `twig.folder`，填一个文件夹，新建的 Twig 文件都放在它下面。这个文件夹在工作区外时，AI 读写会弹确认，参照原则 2 把它加给 AI。
